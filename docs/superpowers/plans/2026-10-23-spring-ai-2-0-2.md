# 기존 practice를 Spring AI 2.0.2(MCP SDK 2.1.0)로 올리기 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Spring AI를 쓰는 MCP 인가 practice 7개와 local-client 4개, `mcp-2026-07-28`의 버전을 올리고, SDK 2.1.0·Spring AI 2.0.2의 새 기능으로 우회 코드를 줄이며, session 상한·만료와 오류 본문의 stack trace를 끝내고, 문서를 맞춘다.

**Architecture:** 먼저 버전만 올려 practice마다 compile·테스트를 확인하고(spike하지 않은 practice 포함), deprecated API를 바꾼다. 그다음 기능 단위로 고친다: local-client step-up은 SDK 재시도에 맡기고, visibility·cimd의 목록은 SDK tool filter로 거르며, streamable 서버(official·chat-memory·authz)는 transport bean을 직접 만들어 session 상한·만료와 오류 본문 filter를 넣고, agent는 만료된 session의 호출을 한 번 다시 보낸다. 마지막에 캡처와 문서를 맞춘다.

**Tech Stack:** Java 21, Spring Boot 4.1.2, Spring Security 7.1.2, Spring AI 2.0.2, MCP Java SDK 2.1.0(`mcp`, `mcp-core`, `mcp-json-jackson3`), community `mcp-*-security-spring-boot` 0.1.14. `mcp-2026-07-28` 서버만 SDK 2.2.0-M1.

**Spec:** `docs/superpowers/specs/2026-10-23-spring-ai-2-0-2-design.md`

## Global Constraints

- 대상 practice: `mcp-security-authn-official`, `mcp-security-authn-chat-memory`, `mcp-security-authn-community`, `mcp-security-authz`, `mcp-stateless-handle`, `mcp-tool-visibility`, `mcp-cimd`. `mcp-2026-07-28`은 Boot와 agent의 Spring AI만. 그 밖의 practice(`agent-mcp`, `agent-mcps`, `chat-memory`)는 건드리지 않는다.
- 버전: 모든 Spring module의 Boot plugin `4.1.2`, `springAiVersion` `2.0.2`. `mavenBom "io.modelcontextprotocol.sdk:mcp-bom:2.0.1"` override와 그 주석은 지운다. local-client는 `io.modelcontextprotocol.sdk:mcp:2.1.0`. community module은 `0.1.14` 그대로. `mcp-2026-07-28` 서버의 `mcp:2.2.0-M1`과 agent의 `mcp-core`·`mcp-json-jackson3` `2.2.0-M1`은 그대로.
- 새 설정: `mcp.limits.max-sessions`(기본 `1000`), `mcp.limits.session-idle-timeout`(기본 `30m`, chat-memory는 `1h`). 상한을 넘은 `initialize`는 `503`, 만료된 session의 요청은 `404`(Spring AI transport의 값 그대로).
- 오류 본문: transport가 쓰는 오류 응답은 `{"jsonrpc":"2.0","id":…,"error":{"code":…,"message":…}}`만 남긴다. status와 code는 SDK·Spring AI가 정한 값 그대로 둔다. 깨진 `id`/`jsonrpc` 본문은 `400` `-32600`이다(SDK 2.1.0).
- local-client의 `[1]`\~`[7]` 출력 문구와 번호는 그대로다. `[7]`은 `StepUp` handler가 `true`를 돌려주기 직전에 찍는다.
- 포트·이름·cookie·계정·scope·tool 목록은 각 practice 그대로다.

- `.superpowers/`, `logs/`, `build/`, `.gradle/`, `certs/`, `.claude/worktrees/`는 `git add`하지 않는다.
- 커밋 메시지 끝 줄: `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. step-up이 걸린 질문 도중에 session이 만료되어도, 재시도 감싸기가 `StepUpRequiredException`(403)을 삼키거나 다시 보내지 않고 그대로 채팅의 consent 카드로 올려야 한다. — Task 8 `step_up_예외는_다시_보내지_않고_그대로_올린다`.
2. session 없음(`404`)이 아닌 실패(시간 초과, 연결 끊김, `isError` 결과)는 다시 보내지 않아야 한다. 쓰기 tool이 두 번 실행될 수 있기 때문이다. — Task 8 `session_없음이_아닌_실패는_다시_보내지_않는다`.
3. `sub`가 없는 token(또는 역할 표에 없는 사용자)의 `tools/list`는 오류가 아니라 손님 기준 목록이어야 한다(tool filter가 예외를 던지면 SDK가 목록 전체를 `-32603`으로 바꾼다). — Task 4 `sub_없는_token의_목록은_손님_목록이다`.
4. session 상한에 닿은 뒤 만료로 자리가 비면 새 `initialize`가 다시 성공해야 한다(상한이 영구 잠금이 되면 안 된다). — Task 5 `만료로_자리가_비면_다시_initialize할_수_있다`.
5. 이미 열린 session 안에서 보낸 깨진 본문(`tools/list`의 `id`가 객체)도 `initialize`와 같이 `400`이고 본문에 `stackTrace`·class 이름이 없어야 한다. — Task 5 `session_안의_깨진_본문도_내부_정보가_없다`.
